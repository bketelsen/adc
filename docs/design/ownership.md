# Continuing ownership: first slice

Permanent agents can own explicit areas with human-maintained intent and versioned agent understanding. Areas are opt-in; creating one does not start work or grant access. The Areas page displays intent, understanding, outstanding follow-ups and links to originating and verification assignments. All organization members share visibility and can edit intent or cancel an obligation with a reason.

`adc_owner` supplies bounded current context or inspects a named area in the same organization. `adc_remember` updates only the calling permanent owner's understanding and source at an explicit revision. It cannot change human intent. Previous area revisions are retained. Observation text and source references are evidence, not additional authority.

`adc_followup` records a later read-only verification under the source assignment's scope. It requires an owned area, stable key, owed outcome, criteria, authorization basis and future due time. Exact repeated calls return the existing obligation. Different content under that key returns a conflict. Initial bounds are four obligations per source assignment, twelve unresolved per owner, one year to the due time, and 48 total activations across the verification assignment. These are first-slice controls, not a complete configurable effort policy. Verification tasks cannot recursively create follow-up chains.

After the source assignment completes and the due time arrives, the scheduler validates owner, source disposition, funding membership, connections and role access. It atomically creates one verification assignment and links the obligation. Funding is pinned to the source human's selected accounts; no account is discovered implicitly. Connection ceilings remain constrained. Protected capability snapshots copy only assignment-scoped read grants without one-time operation bindings; publication is disabled. Advisory execution remains advisory, including broadly credentialed native tools. A recorded authorization basis is agent-reported context, not a technical proof that arbitrary prose describes an in-scope action.

The substantive verification worker records `adc_obligation_result` with pass/fail, observed facts and an evidence reference before finishing. The observation is part of its independent review revision. Root completion retains existing review requirements. The obligation resolves only after the verification assignment completes and its current observations have independent passing reviews and no failing observation. A completed verification activity reporting failure retains a blocked obligation.

Source pause/cancellation, a superseded source run, missing funding/access or cancellation of verification retains a visible blocker rather than manufacturing a new assignment. Cancelling an obligation pauses and stops its unfinished verification. Gateway and standard execution paths recheck obligation/source validity. An expired activation or restart is not permission to replay an external mutation.

P1 retains blockers for reassessment; owner inboxes, automatic supervisor recovery of these obligations, richer deadlines and effort accounting arrive in P3/P4. Discovery interviews and selected-text knowledge correction arrive in P2. The current area page uses ordinary navigation/forms; live briefing and richer pagination arrive with the interface phases. Do not claim these later behaviors are already delivered.

New area/obligation records are additive. Existing task IDs, approvals, schedules, plans and review pins are unchanged when no obligation observation exists. Do not downgrade to an older binary with active verification assignments: the older engine does not understand their source-validity checks. Pause new attention and reconcile active verification before any rollback. A full knowledge export UI and general schema migration framework are not included in this slice.
