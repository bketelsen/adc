# Completion that fits the responsibility

Assignments have a human-selected completion mode. Routine is the default: the accountable owner finishes on concrete evidence (registered code, a saved document, or an observed verification) and the human reviews the result, as they would a colleague's pull request. Reviewed is the opt-in engineering contract: every run that registers code, saves a deliverable document or performs implementation needs a passing review from a different model family, the supervisor delegates finalization of its own artifacts, and execution-plan steps name a designated reviewer. These are two small named policies, not a workflow language or a hard-coded list of domains.

The assignment form and proposal acceptance offer the choice directly; an area can carry a default for work created under it. The assignment saves a versioned policy when it starts. Area edits affect new work, not existing assignments or their later verification obligations. Nil on historical work always means reviewed; the default moving to routine never reinterprets a stored record. Old schedule templates do not acquire new area defaults, and follow-up funding copies the originating work's policy. A routine policy changes completion checks, never authority, credentials, access, publication or membership.

Under routine, code, documents and plan steps complete without a mandatory reviewer; steps may omit `Reviewer`, and an optional review that asks for changes still holds the step. One exception stands under either policy: draft PR delivery requires a passing cross-family review of the exact commit ADC publishes, so a routine assignment with publication authorized arranges that single review for the run that registered the code (`adc_delegate` with `ReviewOf`), and status lists it under `review_needed`. Bounded recurring owner assessments retain their independently reviewed area observations and briefing. Optional expert review remains available everywhere.

`adc_evidence` stores bounded observed completion evidence with a source reference and revision. A routine owner may record it directly; reviewed work uses a substantive specialist. References are labels, not fetch instructions: one line, no credentials, URL query or fragment. Updated evidence participates in review pins. Cancelled, superseded or unfinished worker evidence cannot satisfy completion. Generic evidence does not replace a linked obligation's `adc_obligation_result`: that record must exist before a verification assignment finishes, and the saved policy determines its review requirement. Failed observed verification can finish the assessment while the owed outcome remains blocked.

The Areas form selects the policy, the assignment form selects responsibility, and task metadata shows the saved policy. Proposal refinement can change the selected area before acceptance. Changing a recurring assessment proposal explicitly to one-off removes its recurrence policy while keeping it pending; editing numeric attention limits retains the earlier proposal revision unchanged.

`adc_status` offers focused summary, run, review, assessment, connections, proposals and document views so coordination need not repeatedly consume the whole snapshot. Empty View keeps the legacy full response. Focused run reads stay inside the same assignment and organization. Already-finished child work is a normal `adc_wait` response; the provider yields only if a wait actually changed run state. Candidate-review tools are offered only to planned workers, and routine-owner evidence tools are not offered to reviewed supervisors or reviewers who cannot use them.

Qualification separates two questions: whether an activity finished and whether its wider outcome is verified. An experimental graphics milestone can finish under review while hardware validation remains owed. An external tester's claim cannot directly record a result on an unrelated internal verification task or change human intent.

The same core is exercised with a timed family confirmation, a NAS protection follow-up and a product/delivery investigation. Live fixtures use supplied synthetic evidence, not real family arrangements, infrastructure health or measured hosting costs. Existing production organizations remain reviewed unless a human deliberately changes an area's mode. No new permanent team or speculative maintenance is created by selecting a policy.
