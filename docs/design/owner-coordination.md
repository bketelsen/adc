# Owner coordination seam

P3 extends the existing run messenger with requests addressed to permanent agents in the same organization. A request retains its lead, answerable supervisor, source task/run, question, acceptance criteria, evidence reference and eventual response. Completion of the source run does not discard the request. Source cancellation suppresses it; no request can resurrect cancelled work.

Initial delivery uses a receiving owner's existing authorized active work context. Receipt changes neither its account, tools, authority, approval state nor assignment objective. The receiving owner assesses whether it can answer from existing knowledge or perform in-scope work. A request requiring additional authority remains a visible dependency; it does not borrow the sender's credentials or automatically start an unfunded run. Responses are attributed evidence, not independent verification or human approval.

Delivery is persisted and deduplicated. A claim associates a request with one existing receiving run; a completed, cancelled or unavailable receiver without an answer releases the claim for another valid context. Source completion and engine restart preserve routing. Request/response context is bounded and separates agent correspondence from human steering. No automatic response-to-response conversation is created.

The first queue has a stable caller key, per-source creation limits and per-owner outstanding limits. Reassignment retains request identity, history and spent execution effort. Exhausted or unauthorized work remains visible while independent work continues. Background activation without an existing valid receiving context requires a deliberately funded attention policy; discovering an area does not silently establish that policy.

Cross-area delivery keeps one lead and the source assignment's accountable supervisor. A lead transfer changes coordination responsibility, never permissions. Organization humans can inspect and cancel requests with a reason. Keeping the request visible after an originating task completes supplies a concrete handoff into the later supervisor briefing and bounded attention cycle.

## Implemented first queue

The tools are `adc_owner_request`, `adc_owner_inbox`, `adc_owner_respond`, and `adc_owner_lead`. Ordinary run messaging remains unchanged. The Coordination page shows requests with leads, supervisors, source/transcript links, response evidence and explicit wait reasons; disclosure starts collapsed and pages contain at most 40 requests. Humans can cancel a request without cancelling unrelated receiving work.

The scheduler attaches only to already running or queued owner runs, never wakes a waiting run through its existing plan, review, milestone or external-wait gate, and never creates an assignment. Source-completed requests and responses remain available to later authorized contexts. Blocked responses release their receiving claim, so a later owner run with new evidence can answer. That recovery does not automatically redeliver the same blocker. Candidate searches are reused once per owner per scheduler pass; run records are reloaded before appending to avoid losing simultaneous messages.

Limits are four requests per originating assignment, sixteen unresolved per recipient, and three receiving attempts that end without a substantive response. Lead changes retain those counters and the original supervisor. These controls bound this queue; broader ongoing recovery policies and deliberately funded background activation remain later work. If no eligible owner run exists, the request states that it is waiting for an authorized work context. No human has to copy its evidence or repair its identifier to retain it.

Qualification includes actual SQLite close/reopen, source completion/cancellation, different receiving-human account/scope preservation, lost-response retry, no-wake wait gates, later-run blocker recovery, attempt limits, lead history and browser cancellation. A real Sol/Opus recipient completed the cross-assignment scenario; a second run recovered a retained earlier evidence blocker. The latter recovered three orchestration tool errors (`adc_submit_review` outside a plan, a finished-child `adc_wait` race, and review delegation before author completion). It completed without human continuation; do not label that run zero-friction. Tool discoverability/category policy should address those remaining ordinary-workflow rough edges in P5.
