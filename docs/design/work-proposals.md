# Work proposals

Agents use `adc_propose_work` to suggest bounded future work outside the current assignment's authorized scope. A proposal records an outcome, rationale, scope, completion criteria, evidence, dependencies and suggested owner. ADC links it to its originating assignment/run and can pin a source document revision. Creating a proposal does not create an execution assignment, request routine continuation permission or block current work.

The **Proposals** page is shared by all organization members. Pending proposals appear separately from accepted and declined history, with twelve rows per page and live updates. The Work overview links to the pending queue. Humans can also use **Ask for proposals** to have an agent consider existing document evidence.

- **Edit** saves a new revision while preserving the original evidence chain and previous packet.
- **Discuss** opens a proposal conversation under the human's selected account. The agent can read organization documents, answer and revise the pending proposal. Its allowed tool list contains only ADC status, document reading, proposal creation/revision, blocked reporting and discussion completion; no MCP servers, execution tools or delegation are attached. Replies and human decisions appear in the shared conversation. Live replies do not replace an in-progress form. A concurrent revision displays a reload notice, and stale form submissions are rejected.
- **Decline** records the human's reason. Later agent revisions cannot change a resolved proposal.
- **Accept** requires a personal subscription, accountable agent, explicit authority and authorized scope. The suggested specialist's reporting supervisor is the default accountable agent; humans may choose another. For one-off work, acceptance atomically records the decision and queues one normal assignment, with links back to the accepted proposal and original evidence. Repeated or simultaneous accepts return the existing assignment rather than starting more work. Standard execution, recovery and independent-review gates apply to that assignment.

Questions and proposal conversations are not execution approval. They finish without assembling independent reviewers for the proposal itself; the human queue is the next gate. A human's account is never selected from another member's portfolio. Organization membership and CSRF checks protect the queue and its actions.

Exact repeated title/scope/cadence submissions reuse the existing proposal, including accepted/declined proposals. Title overlap suggests related proposals and existing assignments for comparison; this is a lexical hint, not a semantic duplicate guarantee. Dependencies are explicit planning text acknowledged at acceptance and carried into the execution brief; there is no dependency scheduler in this release.

A proposal may include a structured cadence, validation plan and rollback/stop plan. Human approval of recurring work atomically creates one schedule instead of an immediate assignment. The approval identifies its funding human/account, accountable agent, exact scope and authority; recurring operational actions require validation and rollback/stop plans. Editing the cadence creates a new proposal revision, invalidating stale approval forms. See [standing work](standing-work.md) for timing, recurrence and operational limits. Ordinary execution authority remains advisory where agents have broad shell access; the proposal conversation's narrow tool list does not claim installation-wide isolation. Acceptance alone does not authorize merge, external publication or deployment.
